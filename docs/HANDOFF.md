# 历史交接：现有 Electron 版内存优化

更新：2026-11-17

- **工作目录**：`D:\HIVE context\0.1.0`。只维护 Windows 版，网页版冻结；`prototype` 是旧版对照。

## 下一轮顺序

1. **先测基线**：使用生产构建、隔离文档和用户数据，排除开发服务器／DevTools；测单窗口无 AI、多窗口、复杂大文件、反复开关后回落。统计应用全部相关进程（包括文件服务）的私有提交、工作集及峰值，GPU 单列；避免共享页重复相加，不靠强制清空工作集制造低占用。
2. **减少重复全文处理**：`src/app/App.tsx` 的会话更新／脏状态有重复 `doc.toString()`，包含正文未变的更新；先保证非正文变化不触发全文比较，并保留撤销至已保存状态的正确性。
3. **预览与统计**：`src/features/editor/markdownPresentation.ts` 独立全文解析；`markdownDisplay.ts` 构建装饰；`statusModel.ts` 全文统计及临时数组。评估增量更新、复用语法结果和可见区域资源，保留 Markdown／表格／标注正确性。
4. **多视图与冷会话**：`src/features/files/useFileActions.ts` 同文件多视图重新 makeState；`editorSessionTypes.ts`／App 的 sessions 按编辑区管理；隐藏组合标签仍可能挂载 EditorView。逐步统一文档所有权，视图独立保存选区／滚动；关闭会话及历史预算先明确取舍。
